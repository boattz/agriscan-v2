ทั้งโปรเจกต์พูดเป็นภาษาคน คืออะไร?

ถ้ายังไม่เคยเห็นโปรเจกต์นี้มาก่อน อ่านส่วนนี้ก่อน — จะเข้าใจภาพรวมทั้งหมดโดยไม่ต้องรู้อะไรเลย แล้วค่อยอ่านโค้ดทีละส่วนต่อ

เปรียบเหมือน
🌱 "ไม้วัดดิน" ที่ต่อเน็ตได้
เอาแท่งเซ็นเซอร์ปักลงดิน → มันวัดได้ 7 อย่าง (ความชื้น อุณหภูมิ เค็ม/pH ธาตุอาหาร) → ส่งขึ้นอินเทอร์เน็ต → เปิดดูจากมือถือที่ไหนก็ได้ พร้อมคำแนะนำว่าควรรดน้ำหรือใส่ปุ๋ยอะไร
ของ 4 ชิ้น
🧩 ระบบแบ่งเป็น 4 ส่วน
1) เซ็นเซอร์ (รู้สึก) → 2) ESP32 (คิด+ส่ง) → 3) คลาวด์ (จำ) → 4) หน้าเว็บ (โชว์) — แต่ละส่วนใช้ภาษาคอมพิวเตอร์คนละภาษา ทำคนละหน้าที่
หนึ่งรอบการทำงาน
🔄 วนเป็นวงกลมทุกนาที
ESP32 อ่านค่าเซ็นเซอร์ทุก 3 วินาที → ส่งขึ้นคลาวด์ทุก 3 วินาที → หน้าเว็บถามคลาวด์ทุก 3 วินาทีว่ามีค่าใหม่ไหม → โชว์บนจอ + บอกคำแนะนำ
ศัพท์ที่เจอในเอกสารนี้ — แปลเป็นภาษาคน
ศัพท์แปลเป็นภาษาคนในโปรเจกต์นี้คือ
เซ็นเซอร์ (Sensor)อุปกรณ์ที่รู้สึกได้เหมือนประสาทสัมผัสแท่งเหล็กปักดิน วัดได้ 7 ค่า
ESP32คอมพิวเตอร์จิ๋วราคาถูก มี WiFi ในตัวสมองของระบบ — อ่านค่า ส่งต่อ เสิร์ฟหน้าเว็บ

Backendฝั่งเซิร์ฟเวอร์ที่เก็บข้อมูลapp.py (Python/Flask) บน Render
Frontend / Dashboardฝั่งหน้าจอที่คนเห็นโฟลเดอร์ dashboard/ (HTML/CSS/JS)
Databaseตู้เอกสารเก็บข้อมูลPostgreSQL (บนคลาวด์) / SQLite (ในเครื่อง)

01 — ภาษา

โปรเจกต์นี้ใช้ภาษาอะไรบ้าง?

ทั้งหมด 6 ภาษา แต่ละภาษาทำหน้าที่ของตัวเอง คนละชั้น คนละงาน

ภาษาใช้ที่ไหนทำหน้าที่อะไรระดับ
C++ (Arduino) esp32/agriscan/agriscan.ino สั่งงานฮาร์ดแวร์โดยตรง: อ่านเซนเซอร์ RS485, เชื่อม WiFi, รันเว็บ, ส่งข้อมูลขึ้นคลาวด์ ใกล้ฮาร์ดแวร์
HTML dashboard/index.html โครงสร้างของหน้าเว็บ — วางการ์ดเซ็นเซอร์, ปุ่ม, แบนเนอร์ โครงสร้าง
CSS dashboard/style.css ตกแต่งหน้าตา — ธีมเขียวเข้ม, การ์ดกระจก, แอนิเมชัน, responsive หน้าตา
JavaScript dashboard/script.js สมองฝั่งเว็บ — ดึงข้อมูลทุก 5 วิ, ไล่หาแหล่งข้อมูล, คำนวณคำแนะนำ, อัปเดตหน้าจอ สมองฝั่ง client
Python (Flask) backend/app.py สมองฝั่ง server — รับค่าจาก ESP32, เก็บลง PostgreSQL, เสิร์ฟหน้าเว็บและ API สมองฝั่ง server
YAML render.yaml ตั้งค่า deploy บน Render — บอกให้สร้างเว็บ + ฐานข้อมูลอัตโนมัติ ตั้งค่า
กฎเหล็กของโปรเจกต์ Dashboard เป็น Vanilla HTML/CSS/JS — ไม่มี framework (React, Vue ฯลฯ) และไม่มี build step: เปิดไฟล์ .html ได้เลยทันที ทุกอย่างอ่านแล้วเข้าใจได้ ไม่มีของที่ถูก "ซ่อน" ไว้

03 — Workflow

ภาพรวม workflow ของทั้งระบบ

ข้อมูลเดินทางจากดิน → ชิป → อินเทอร์เน็ต → ฐานข้อมูล → หน้าจอผู้ใช้ ตามลำดับนี้

1

🌱 เซ็นเซอร์วัดค่า

เซ็นเซอร์ 7-in-1 อ่านค่าดิน 7 อย่าง พร้อมรับคำสั่งผ่านสาย RS485 (Modbus RTU, slave ID 1)

2

🔌 ESP32 อ่านค่า (C++)

loop() ส่งคำสั่ง readHoldingRegisters(0x0000, 7) ทุก 3 วินาที → แปลง raw เป็นหน่วยจริง (เช่น ÷10)

3

⚙️ ESP32 ทำ 2 หน้าที่พร้อมกัน

เสิร์ฟ local: ตอบ GET /data ให้คนในบ้าน/ไร่ · ส่งคลาวด์: POST /api/readings (HTTPS) ทุก 3 วินาที

4

☁️ Flask รับและเก็บ (Python)

ตรวจ X-API-Key → INSERT เข้า PostgreSQL → ตอบ 201

5

🖥️ Dashboard ดึงและแสดง (JS)

poll GET /api/latest ทุก 3 วินาที → อัปเดตการ์ด + คำนวณคำแนะนำอัตโนมัติ

หัวใจของ workflow ระบบเป็นแบบ ESP32 เป็นผู้ส่ง (push) ไม่ใช่ dashboard เป็นผู้ไปขอ (poll) จาก ESP32 — เพราะ ESP32 อยู่ในเครือข่ายบ้าน/ไร่ ไม่มี IP สาธารณะ จึง "ส่งออก" ไปหาคลาวด์เอง แล้วคนดูค่อยมาอ่านจากคลาวด์ กลับทิศทางนี้ทำให้ดูได้จากทุกที่
04 — ESP32 Firmware (ภาษา C++)

agriscan.ino — อธิบายทีละส่วน

โค้ดเดียวที่รันบนชิป ทำ 4 หน้าที่: อ่านเซนเซอร์, เสิร์ฟเว็บ local, ส่งคลาวด์, ทนทานต่อความผิดพลาด

โครงสร้าง 2 ฟังก์ชันหลัก (กฎของ Arduino)
void setup() { /* รันครั้งเดียวตอนเปิดเครื่อง */ }
void loop()  { /* รันซ้ำ ๆ ตลอดไป */ }
① ยืมไลบรารี (include)
#include <ModbusMaster.h>     // ไลบรารีสำหรับคุยกับเซนเซอร์ RS485
#include <WiFi.h>             // เชื่อม WiFi
#include <WebServer.h>        // ทำเว็บเซิร์ฟเวอร์
#include <HTTPClient.h>       // ส่ง HTTP ขึ้นคลาวด์
#include <WiFiClientSecure.h> // HTTPS (เข้ารหัส)
#include <ESPmDNS.h>          // ชื่อ agriscan.local

เหมือนเปิดตู้ยืมเครื่องมือ: <ModbusMaster.h> = คู่มือคุยกับเซนเซอร์, <WebServer.h> = ชุดทำเว็บ เป็นต้น

② ตั้งค่าคงที่ — ป้ายชื่อแทนตัวเลข
const char* WIFI_SSID = "YOUR_WIFI_SSID";       // ชื่อ WiFi
const char* CLOUD_URL = "https://...onrender.com/api/readings"; // ปลายทางคลาวด์
const char* API_KEY   = "...";                  // รหัสยืนยันตัวตน
#define RXD2   16      // ขา 16 = ขารับข้อมูล RS485
#define BAUD_RATE 4800 // ความเร็วคุยกับเซนเซอร์
③ ฟังก์ชัน readSensor() — สั่งเซนเซอร์วัดค่า
SoilData readSensor() {
  // สั่งอ่าน Holding Registers 0x0000 จำนวน 7 ตัวในครั้งเดียว
  node.readHoldingRegisters(0x0000, 7);
  // แปลง raw → หน่วยจริง (เซนเซอร์ส่งค่ามา ×10)
  d.moisture    = buf[0] / 10.0;          // ความชื้น %
  d.temperature = (int16_t)buf[1] / 10.0; // อุณหภูมิ °C (int16 รองรับค่าลบ)
  d.ec          = buf[2];                 // EC µS/cm
  d.ph          = buf[3] / 10.0;          // pH
  d.n           = buf[4];                 // N mg/kg
  d.p           = buf[5];                 // P mg/kg
  d.k           = buf[6];                 // K mg/kg
}
④ setup() — เตรียมเครื่องครั้งเดียว
void setup() {
  Serial.begin(115200);                 // เปิดจอคอมสำหรับ debug (Serial Monitor)
  WiFi.mode(WIFI_STA);                  // โหมด WiFi client
  connectWiFi();                        // ต่อ WiFi (ลอง 20 ครั้ง ครั้งละ 0.5 วิ)
  MDNS.begin("agriscan");            // ตั้งชื่อ http://agriscan.local
  server.on("/", ...);               // เส้นทางเว็บ: หน้า dashboard
  server.on("/data", handleData);    // เส้นทางเว็บ: ส่งค่า JSON
  Serial2.begin(4800, SERIAL_8N1, 16, 17); // เปิดพอร์ตคุยกับเซนเซอร์
  node.begin(1, Serial2);               // ตั้งค่า Modbus slave ID = 1
}
⑤ loop() — วงจรทำงานซ้ำ (หัวใจของระบบ)
void loop() {
  server.handleClient();   // 1. รับคำขอจากเว็บ (ตอบได้ตลอดเวลา)

  checkWiFi();             // 2. WiFi หลุดไหม? ถ้าหลุด reconnect อัตโนมัติ

  // 3. อ่านเซนเซอร์ทุก 3 วินาที
  if (millis() - lastRead >= 3000) {
    SoilData d = readSensor();
    if (d.valid) lastData = d;   // สำเร็จ → เก็บค่า
    // ไม่สำเร็จ → ใช้ค่าเดิม (ระบบทนทาน)
  }

  // 4. ส่งคลาวด์ทุก 3 วินาที
  if (millis() - lastUpload >= 3000) {
    uploadReading();       // POST ไป Render
  }
}
⑥ uploadReading() — ส่งค่าขึ้นคลาวด์
void uploadReading() {
  WiFiClientSecure client;   // สาย HTTPS
  client.setInsecure();      // ไม่ตรวจใบรับรอง (พอสำหรับงานสาธิต)
  http.addHeader("X-API-Key", API_KEY); // ใส่รหัสยืนยันตัวตน
  int code = http.POST(body);   // ส่ง JSON ไปยัง /api/readings
  // code 201 = สำเร็จ · อื่น ๆ = ล้มเหลว (ลองใหม่รอบถัดไป)
}
เทคนิคที่น่าสนใจในโค้ดนี้ ใช้ค่าเดิมเมื่ออ่านไม่ได้ — ถ้า Modbus ล้มเหลวชั่วคราว (สัญญาณรบกวน, สายหลวม) ระบบไม่พัง แต่แสดงค่าล่าสุดที่อ่านได้ และ WiFi auto-reconnect ทำให้ฝังไว้ในไร่ได้โดยไม่ต้องไปรีเซ็ต

② fetchData() — ไล่หาข้อมูลตามลำดับ (fallback chain)
async function fetchData() {
  const candidates = [];
  // 1. IP ที่ผู้ใช้ตั้งเอง (localStorage) → 2. URL ที่ใช้ได้ล่าสุด
  // 3. หน้าเว็บที่เปิดอยู่ → 4. คลาวด์ Render → 5. agriscan.local ...

  for (const url of candidates) {
    try {
      // AbortController = ตัด timeout 3 วินาที ไม่รอค้าง
      const ctrl = new AbortController();
      const res = await fetch(url, { signal: ctrl.signal });
      const json = await res.json();
      updateUI(json);   // เจอแล้ว! วาดหน้าจอ
      break;
    } catch (err) { /* ลอง URL ถัดไป */ }
  }
}
③ updateUI() + buildRecommendations() — วาดหน้าจอและแนะนำ
function updateUI(d) {
  // ความชื้น: อัปเดตตัวเลข + กราฟแท่ง + สีเปลี่ยนตามสถานะ
  if (d.moisture < 30)      bar แดง → "ดินแห้ง ควรรดน้ำ"
  else if (d.moisture > 80) bar น้ำเงิน → "ชื้นเกินไป"
  else                    bar เขียว → "ปกติ"

  // NPK: เทียบเกณฑ์กรมพัฒนาที่ดิน
  if (d.p < 10)  → "P ต่ำ"      // ต่ำ <10, ปานกลาง 10–25, สูง >25
  if (d.k < 60)  → "K ต่ำ"      // ต่ำ <60, ปานกลาง 60–90, สูง >90

  buildRecommendations(d);  // สร้างการ์ดคำแนะนำ (เช่น "ใส่ปุ๋ย 0-46-0")
}

06 — Backend (ภาษา Python / Flask)

app.py — อธิบายทีละส่วน

Flask = framework ทำเว็บที่เล็กสุดใน Python — ไฟล์เดียวทั้งรับค่า เก็บฐานข้อมูล และเสิร์ฟหน้าเว็บ

① เตรียม config — อ่านค่าจาก environment
from flask import Flask, jsonify, request, send_from_directory
from flask_cors import CORS

07 — Deployment (render.yaml)

ขึ้นคลาวด์ยังไง? — เกือบไม่ต้องทำอะไร

Render อ่านไฟล์ตั้งค่า render.yaml แล้วสร้างทุกอย่างให้อัตโนมัติ: เว็บ + ฐานข้อมูล + รหัสลับ

render.yaml — ประกาศสิ่งที่ต้องการ
services:
  - type: web
    rootDir: backend            # ไปรันที่โฟลเดอร์ backend
    startCommand: gunicorn app:app  # รัน Flask ด้วย gunicorn
    envVars:
      - key: API_KEY        # สุ่มให้อัตโนมัติ
      - key: DATABASE_URL
        fromDatabase:
          name: agriscan-db  # ผูกกับฐานข้อมูลด้านล่าง
databases:
  - name: agriscan-db
    plan: free
ขั้นตอนจริง (Blueprint)
  1. Push โค้ดขึ้น GitHub
  2. Render → New → Blueprint → เลือก repo
  3. Render สร้าง Web Service + PostgreSQL และสุ่ม API_KEY ให้
  4. ได้ URL เช่น https://agriscan-v2.onrender.com ใช้ได้ทันที
  5. เอา API_KEY ไปใส่ใน agriscan.ino → flash ESP32
ทำไมต้อง gunicorn? Flask รันในตัว (dev server) ไม่เหมาะกับงานจริง — gunicorn คือเว็บเซิร์ฟเวอร์สำหรับ production ที่รัน Flask ได้เสถียร รองรับหลาย request พร้อมกัน
08 — ตัวอย่างเส้นทางข้อมูล

เกิดอะไรขึ้นในแต่ละฉาก?

จำลอง 2 สถานการณ์จริงเพื่อให้เห็นภาพว่าโค้ดแต่ละส่วนถูกเรียกเมื่อไหร่

ฉากที่ 1 — ESP32 ส่งค่าขึ้นคลาวด์ (ทุก 3 วินาที)
1. ESP32 (C++)
   loop() เห็นเวลาครบ 3 วินาที → uploadReading()
   → POST https://agriscan-v2.onrender.com/api/readings
     headers: X-API-Key, Content-Type: application/json
     body: {"moisture":45.2, "temperature":28.5, ...}

2. Flask (Python)
   add_reading() ตรวจ X-API-Key ตรง? → INSERT ลง PostgreSQL → ตอบ 201

3. ฐานข้อมูล
   readings(id, moisture, temperature, ec, ph, n, p, k, valid, created_at) ← บรรทัดใหม่
ฉากที่ 2 — ผู้ใช้เปิด dashboard จากมือถือ
1. Browser → GET https://...onrender.com/
   Flask เสิร์ฟ index.html + style.css + script.js

2. script.js (JS) ทำงานทันที
   startPolling() → fetchData()
   → ไล่ candidates: origin ของเว็บ = คลาวด์ → GET /api/latest

3. Flask → SELECT ค่าล่าสุดจาก PostgreSQL → ส่ง JSON กลับ

4. script.js → updateUI() → วาดการ์ด + buildRecommendations()
   เช่น ความชื้น 45% → การ์ดเขียว "ปกติ" · P=32 → "P สูง" ตามเกณฑ์กรมฯ
ถ้า ESP32 ยังไม่เคยส่งค่า GET /api/latest จะตอบ 404 "ยังไม่มีข้อมูล" → dashboard แสดงสถานะ offline ตามจริง (ไม่มีการปลอมข้อมูล) และลองใหม่ทุก 3 วินาที
