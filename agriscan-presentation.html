01 — ภาพรวม

โปรเจกต์นี้คืออะไร?

Agriscan คือระบบ IoT สำหรับการเกษตร ตรวจวัดสภาพดิน 7 อย่างแบบเรียลไทม์ ตั้งแต่ระดับฮาร์ดแวร์จนถึงแดชบอร์ดบนเว็บ — สร้างด้วยหลักการ "เรียบง่ายที่สุดที่ใช้งานได้จริง"

01 · ฮาร์ดแวร์
ESP32 + เซ็นเซอร์ 7-in-1
เซ็นเซอร์ฝังดินอ่านค่า 7 อย่างพร้อมกัน (ความชื้น, อุณหภูมิ, EC, pH, N, P, K) ส่งผ่านสาย RS485 Modbus เพียง 2 เส้นให้ ESP32
02 · ตัวกลาง
ESP32 ทำทุกอย่างในตัวเดียว
อ่านค่าเซ็นเซอร์, เสิร์ฟหน้า Dashboard ในเครือข่ายท้องถิ่น (agriscan.local) และ POST ค่าจริงขึ้นคลาวด์ทุก 3 วินาที (HTTPS + API key)
03 · การแสดงผล
Dashboard เว็บ + คำแนะนำ
หน้าเว็บ Vanilla HTML/CSS/JS ดึงข้อมูลทุก 3 วินาที — เปิดบนคลาวด์ดูจากที่ไหนก็ได้ พร้อมวิเคราะห์และแนะนำการดูแลดินอัตโนมัติเป็นภาษาไทย
ทำไมต้องมี 2 โหมด?
โหมด Local (ในไร่)
ESP32 เสิร์ฟเอง — ไม่ต้องมีอินเทอร์เน็ต
เข้า http://agriscan.local ในเครือข่ายเดียวกัน ดูค่าจากเซ็นเซอร์สด ๆ ได้ทันที เหมาะกับพื้นที่ที่อินเทอร์เน็ตไม่เสถียร
โหมด Cloud (ทุกที่)
ข้อมูลจริงบนคลาวด์ — ดูจากมือถือที่ไหนก็ได้
ESP32 ส่งค่าขึ้น Render (Flask + PostgreSQL) ทุก 3 วินาที เปิด https://agriscan-v2.onrender.com จากทุกที่เห็นค่าจริงจากไร่ ไม่มีข้อมูลจำลอง
02 — ศัพท์เทคนิค

ฟังแล้วไม่รู้เรื่อง? แปลเป็นภาษาคนตรงนี้

ก่อนอ่านส่วนต่อไป ขอแปลศัพท์เทคนิคทั้งหมดที่เจอในโปรเจกต์นี้เป็นภาษาง่าย ๆ — อ่านจบส่วนนี้แล้วจะเข้าใจทุกหน้าต่อจากนี้

คำศัพท์พูดเป็นภาษาคน
IoT (Internet of Things) ของใช้ทั่วไปที่ต่ออินเทอร์เน็ตได้ เช่น หลอดไฟเปิดปิดผ่านมือถือ นาฬิกาอัจฉริยะ — โปรเจกต์นี้คือ "ไม้วัดดิน" ที่ต่อเน็ตได้
เซ็นเซอร์ (Sensor) อุปกรณ์ที่"รู้สึก"ได้เหมือนประสาทสัมผัส — ตัวนี้รู้ว่าดินชื้นแค่ไหน ร้อนแค่ไหน มีธาตุอาหารเท่าไหร่
ESP32 ชิปคอมพิวเตอร์จิ๋วราคาไม่กี่ร้อยบาท มี WiFi ในตัว — ทำหน้าที่เป็น "สมอง" ของระบบ คอยอ่านค่าจากเซ็นเซอร์แล้วส่งต่อ
RS485 / Modbus ภาษาที่เซ็นเซอร์กับ ESP32 ใช้คุยกันผ่านสายไฟ 2 เส้น — เหมือนสายโทรศัพท์บ้านที่ส่งสัญญาณได้ไกลและทนสัญญาณรบกวน
Firmware (เฟิร์มแวร์) โปรแกรมที่ฝังอยู่ในชิป คอยสั่งงานฮาร์ดแวร์ — เหมือนระบบปฏิบัติการในเครื่องซักผ้า ไม่ได้เห็นหน้าจอแต่ทำงานตลอดเวลา
API ช่องทางให้โปรแกรมต่าง ๆ คุยกัน — เหมือนพนักงานหน้าร้าน: บอก"ขอดูข้อมูลล่าสุด" พนักงานก็ไปหยิบมาให้ (โดยไม่ต้องเข้าไปในคลังเอง)
JSON รูปแบบการเขียนข้อมูลที่ทั้งเครื่องและคนอ่านเข้าใจ — เหมือนฟอร์มกรอกข้อมูล: {"ความชื้น": 45, "อุณหภูมิ": 28}
คลาวด์ (Cloud) คอมพิวเตอร์ของคนอื่นที่เราเช่าใช้ผ่านอินเทอร์เน็ต — เหมือนฝากของไว้ที่โกดังกลาง เปิดดูจากที่ไหนก็ได้
PostgreSQL โปรแกรมเก็บข้อมูล (ฐานข้อมูล) — เหมือนตู้เอกสารยักษ์ เก็บประวัติค่าดินทุกนาทีไว้เรียงตามเวลา
Dashboard หน้าเว็บที่รวมทุกอย่างไว้ที่เดียว — เหมือนแผงหน้าปัดรถยนต์ เห็นความเร็ว น้ำมัน อุณหภูมิ ในจอเดียว
HTTPS ช่องทางส่งข้อมูลแบบใส่ซองปิดผนึก — กันคนอื่นแอบอ่านข้อมูลระหว่างทาง (เห็นเป็น https:// นำหน้า URL)
API Key รหัสผ่านเฉพาะของระบบ — เหมือนกุญแจห้องส่งของ ใครไม่มีกุญแจส่งข้อมูลเข้ามาไม่ได้
Poll (โพล) การ"ถามเป็นระยะ" — หน้าเว็บถามเซิร์ฟเวอร์ทุก 3 วินาทีว่า"มีค่าล่าสุดไหม" เหมือนเด็กถามแม่ทุก 3 วิว่า"ข้าวสุกยัง"
Deploy (ดีพลอย) การเอาโปรแกรมขึ้นไปรันบนเซิร์ฟเวอร์จริงให้คนอื่นใช้ — เหมือนย้ายงานจากโต๊ะทดลองไปเปิดหน้าร้าน
mDNS สมุดโทรศัพท์ภายในบ้าน — ให้เราเรียก ESP32 ด้วยชื่อ agriscan.local แทนการจำเลข IP ยาว ๆ
จำง่าย ๆ เซ็นเซอร์รู้สึก → ESP32 คิด → คลาวด์จำ → หน้าจอโชว์ — ทั้งโปรเจกต์คือการส่งข้อมูล 7 อย่างวนเป็นวงนี้ทุกนาที
03 — เซ็นเซอร์

ค่าที่วัดได้และเกณฑ์อ้างอิง

ระบบอ่านค่า 7 อย่างจากเซ็นเซอร์เดียวกันผ่านโปรโตคอล Modbus RTU โดยอ่าน Holding Registers 0x0000–0x0006 ต่อเนื่อง 7 ตัวในคำสั่งเดียว เกณฑ์อ้างอิงจากกรมพัฒนาที่ดิน — โดยผู้ใช้เลือก ชนิดพืช (ข้าว / ข้าวโพด / ยางพารา / อื่นๆ) ระบบจะใช้เกณฑ์ของพืชนั้นๆ ในการประเมินและแนะนำ

ที่มา: ศักยภาพการให้ผลผลิตพืชเศรษฐกิจของชุดดินในประเทศไทย (สำนักสำรวจและวิจัยทรัพยากรดิน, กรมพัฒนาที่ดิน) — ตารางที่ 3 (ข้าว) และตารางที่ 4 (ข้าวโพด), ดัดแปลงจากบัณฑิตและคำรณ (2542) · ยางพารา: คู่มือการจำแนกความเหมาะสมของดินสำหรับพืชเศรษฐกิจ (เอกสารวิชาการ เล่ม 28) · EC 1 dS/m = 1,000 µS/cm · ความชื้น (%) เป็นแนวทางรดน้ำ (กรมฯ ใช้เกณฑ์ปริมาณน้ำ mm/ฤดู ไม่ใช่ % ความชื้น) · ชนิดพืชที่เลือกถูกบันทึกใน localStorage และใช้กับทั้ง dashboard และ ESP32 ที่ฝังหน้าไว้ในตัว

ค่าหน่วยเกณฑ์อ้างอิงสถานะผิดปกติความหมาย
ความชื้น (Moisture) %ตามชนิดพืช (ดูตารางเกณฑ์รายพืช) ต่ำกว่าเกณฑ์พืช แห้ง สูงกว่าเกณฑ์พืช ชื้นเกิน น้ำในดิน — ไม่ใช่เกณฑ์กรมฯ ขึ้นกับชนิดดิน (field capacity) ระบบใช้ช่วงเฉพาะของพืชที่เลือก
อุณหภูมิ (Temperature) °Cตามชนิดพืช (ข้อมูลประกอบ) ต่ำกว่าเกณฑ์ เย็น สูงกว่าเกณฑ์ ร้อน ความร้อนในดิน ส่งผลต่อการดูดซึมของราก — ใช้ช่วงอุณหภูมิเหมาะของแต่ละพืช
EC (การนำไฟฟ้า) µS/cmตามชนิดพืช ข้าว ≤2,000 · ข้าวโพด ≤1,500 · ยางพารา ≤1,000 เกินเกณฑ์ของพืช ความเค็มของดิน — เกณฑ์กรมพัฒนาที่ดิน (1 dS/m = 1,000 µS/cm) ยางพาราอ่อนไหวต่อเค็มมากที่สุด
pH ดิน pHตามชนิดพืช ข้าว/ยางพารา 4.5–6.5 · ข้าวโพด 5.5–7.0 ต่ำกว่าเกณฑ์ กรด สูงกว่าเกณฑ์ ด่าง ความเป็นกรด-ด่าง — จัดชั้นตามกรมพัฒนาที่ดิน + ช่วงเหมาะของแต่ละพืช
ไนโตรเจน (N) mg/kgตามชนิดพืช ข้าว/ยางพารา ≥50 · ข้าวโพด ≥60 (ค่าบ่งชี้) ต่ำกว่าเกณฑ์ ธาตุหลัก เร่งใบ — กรมฯ วัด N เป็น % (OM/Total N) ค่าเซ็นเซอร์เป็นค่าประมาณ
ฟอสฟอรัส (P) mg/kgต่ำ <10 · ปานกลาง 10–25 · สูง >25 (ทุกพืช) < 10 ต่ำ 10–25 ปานกลาง เร่งราก ดอก ผล — เกณฑ์กรมพัฒนาที่ดิน (ตารางที่ 15)
โพแทสเซียม (K) mg/kgต่ำ <60 · ปานกลาง 60–90 · สูง >90 (ทุกพืช) < 60 ต่ำ 60–90 ปานกลาง เสริมความแข็งแรง ต้านทานโรค — เกณฑ์กรมพัฒนาที่ดิน (ตารางที่ 15)

จุดน่าสนใจ ค่า EC ไม่ได้วัด "เกลือ" โดยตรง — แต่วัดความสามารถในการนำไฟฟ้าของน้ำในดิน ซึ่งสะท้อนความเข้มข้นของธาตุอาหารที่ละลายอยู่ ถ้าเกิน 2,000 µS/cm (2 dS/m) แปลว่าดินเริ่มเค็มตามเกณฑ์กรมพัฒนาที่ดิน
แหล่งที่มาของเกณฑ์ (กรมพัฒนาที่ดินล้วน) ข้าว / ข้าวโพด: ตารางที่ 3 และ 4 (pH, ECe, อุณหภูมิ) จาก ศักยภาพการให้ผลผลิตพืชเศรษฐกิจของชุดดินในประเทศไทย (สำนักสำรวจและวิจัยทรัพยากรดิน, กรมพัฒนาที่ดิน — ดัดแปลงจากบัณฑิตและคำรณ, 2542) · ยางพารา: pH 4.5–6.5 (เหมาะ 5.6–6.5), EC <1 dS/m จาก คู่มือการจำแนกความเหมาะสมของดินสำหรับพืชเศรษฐกิจ (เอกสารวิชาการ เล่ม 28) + รายงานวิจัยของกรมฯ (ไวต่อเค็ม <0.95 dS/m) · P, K: ตารางที่ 15 (กองสำรวจดิน, 2523) · ระดับความเค็ม EC: ตารางที่ 2 จากสำนักวิทยาศาสตร์เพื่อการพัฒนาที่ดิน (2547): 0–2 ไม่เค็ม · 2–4 เค็มน้อยมาก (กระทบพืช sensitive) · 4–8 เค็มปานกลาง · 8–16 เค็มจัด · >16 เค็มจัดมาก — ลิงก์ตรง: e-library.ldd.go.th/library/flip/bib10134f/files/basic-html/page83.html (ตารางที่ 15) — ส่วน N (mg/kg), ความชื้น (%) และอุณหภูมิ ไม่มีเกณฑ์ตัวเลขจากกรมฯ โดยตรง (N วัดเป็น %, ความชื้นกรมฯ ใช้ mm/ฤดู ไม่ใช่ %) จึงแสดงเป็นค่าบ่งชี้/แนวทางรดน้ำ

06 — Firmware ESP32

ESP32: ตัวกลางแปลงเซ็นเซอร์เป็นเว็บ API

โค้ด Arduino C++ ใน agriscan.ino ทำ 4 หน้าที่หลัก: อ่านค่า Modbus → เก็บค่าในหน่วยความจำ → เสิร์ฟ dashboard ท้องถิ่น → ส่งค่าขึ้นคลาวด์

การเชื่อมต่อ
RS485 ↔ ESP32
RX (รับข้อมูล)GPIO 16
TX (ส่งข้อมูล)GPIO 17
DE/RE (ควบคุม MAX485)GPIO 4
Baud rate4800 · 8N1
Modbus Slave ID1
Web Server + Cloud (พอร์ต 80)
API ของ ESP32
  • GET / → เสิร์ฟหน้า Dashboard (จาก dashboard.h)
  • GET /data → ค่าเซ็นเซอร์เป็น JSON พร้อม CORS เปิดทั้งหมด
  • POST /api/readings → ส่งค่าจริงขึ้นคลาวด์ทุก 3 วินาที (HTTPS + X-API-Key)
  • mDNS → เข้าผ่าน http://agriscan.local ไม่ต้องจำ IP
วงจรการทำงาน
loop() — ทำงานวนซ้ำ
  • รับ HTTP request ผ่าน server.handleClient() ตลอดเวลา
  • ตรวจ WiFi ถ้าหลุด → reconnect อัตโนมัติ
  • อ่านค่าเซ็นเซอร์ผ่าน Modbus (readHoldingRegisters(0x0000, 7)) ทุก 3 วินาที
  • อ่านสำเร็จ → อัปเดตค่า / ไม่สำเร็จ → ใช้ค่าเดิม (ระบบทนทานต่อการขาดการติดต่อชั่วคราว)
  • POST ค่าจริงขึ้นคลาวด์ทุก 3 วินาที — สำเร็จ (201) / ล้มเหลว → ลองใหม่รอบถัดไป
การแปลงค่าจาก Register
Raw → หน่วยจริง
  • ความชื้น = reg[0] / 10
  • อุณหภูมิ = (int16)reg[1] / 10 (รองรับค่าลบ)
  • EC = reg[2] · pH = reg[3] / 10
  • N, P, K = reg[4..6] (mg/kg)

  "ph": 6.8, "n": 45, "p": 32, "k": 89,
  "valid": true }

07 — Dashboard

หน้าแสดงผลและ "สมอง" ของระบบ

แดชบอร์ด Vanilla JS ธีม dark green glassmorphism ภาษาไทย — ดึงข้อมูลทุก 3 วินาที พร้อมระบบหาที่อยู่ของ ESP32 อัตโนมัติ และแนะนำการดูแลดินอ้างอิงเกณฑ์กรมพัฒนาที่ดิน

องค์ประกอบ UI
บนหน้าจอมีอะไรบ้าง
  • Header: โลโก้, สถานะออนไลน์/ออฟไลน์/ข้อมูลเก่า (ไฟกระพริบ), เวลาอัปเดตล่าสุด, ป้ายที่อยู่ที่เชื่อมต่อ (คลิกเปลี่ยนได้), ป้ายแหล่งข้อมูล (🟢 ESP32 ท้องถิ่น · ข้อมูลสด / ☁️ คลาวด์ / 🟡 ข้อมูลเก่า X นาที)
  • การ์ดเซ็นเซอร์ 5 ใบ: ความชื้น (progress bar สีเปลี่ยนตามสถานะ), อุณหภูมิ, EC, pH, NPK (กราฟแท่ง 3 สี)
  • เลือกชนิดพืช: dropdown ข้าว 🌾 / ข้าวโพด 🌽 / ยางพารา 🌳 / อื่นๆ 🌿 — เกณฑ์คำแนะนำเปลี่ยนตามพืชที่เลือก
  • คำแนะนำอัตโนมัติ: การ์ดวิเคราะห์ค่าแต่ละตัวแบบ real-time ตามเกณฑ์ของพืชที่เลือก (ดูตารางด้านล่าง)
  • Banner: แจ้ง "กำลังเชื่อมต่อ" และสถานะ offline — ไม่มีข้อมูลจำลอง
  • ลูกเล่น: ตัวเลขกระพริบเมื่อค่าเปลี่ยน, skeleton loading, ปุ่มรีเฟรช
ระบบแนะนำอัตโนมัติ
ตัวอย่างคำแนะนำ (ภาษาไทย)
  • เกณฑ์เปลี่ยนตามพืชที่เลือก — เช่น เลือกข้าว → ความชื้นควร ≥60% (นาขังน้ำ) แต่เลือกยางพารา → ควร 30–60% (ระบายน้ำดี ไม่แฉะ)
  • ความชื้นต่ำกว่าเกณฑ์ของพืชนั้นๆ → "ควรรดน้ำทันที" / สูงเกิน → "หยุดรดน้ำ — อาจรากเน่า"
  • pH ต่ำกว่าเกณฑ์ของพืช → "ใส่ปูนขาว (Lime) / โดโลไมท์" / สูงเกิน → "ใส่กำมะถัน" (เช่น ข้าว pH ≥4.5, ยางพารา pH 4.5–6.5)
  • N ต่ำ → "ใส่ปุ๋ย 46-0-0 หรือ 21-0-0" — สูตรปุ๋ยเฉพาะพืช เช่น ข้าวโพดเน้น N, ยางพาราใช้ 21-0-0 หรือ 13-13-21
  • P < 10 → "ใส่ปุ๋ย 0-46-0" · 10–25 → "ปานกลาง ยังไม่ต้องใส่" (เกณฑ์กรมฯ ตารางที่ 15)
  • K < 60 → "ใส่ปุ๋ย 0-0-60" · 60–90 → "ปานกลาง ยังไม่ต้องใส่" (เกณฑ์กรมฯ ตารางที่ 15)
  • EC เกินเกณฑ์พืชนั้นๆ → เช่น ยางพารา >1,000 µS/cm → "ดินเค็มเกินไป — งดปุ๋ยเคมี ล้างเกลือ"
  • อุณหภูมิเกินเกณฑ์ → "คลุมดินเพื่อลดความร้อน"
Fallback Chain — ระบบหาตำแหน่งข้อมูลอัตโนมัติ (ลองตามลำดับ)
1IP ที่ผู้ใช้ตั้งเอง (localStorage)จำจาก session ก่อนหน้า
2URL ที่เชื่อมต่อสำเร็จล่าสุดเร็วสุดสำหรับการใช้งานซ้ำ
3Page Origin (หน้าเว็บที่เปิดอยู่)กรณีเปิดผ่าน ESP32 หรือคลาวด์โดยตรง
4https://agriscan-v2.onrender.com/dataคลาวด์ Render — ค่าจริงจาก ESP32
5http://agriscan.local/datamDNS ของ ESP32 (เครือข่ายท้องถิ่น)
6http://192.168.1.1/datagateway ตอนใช้ hotspot
7http://localhost:5000/databackend รันในเครื่อง (dev)
การกันพลาด แต่ละ URL มี timeout 3 วินาที (AbortController) — ไม่มี mock data ถ้ายังไม่มีข้อมูล ระบบจะแสดงสถานะ offline ตามจริงและลองใหม่ทุก 3 วินาที / ทันทีที่กลับมาที่แท็บ จนกว่า ESP32 จะส่งค่ามา

นอกจากนี้ ยังตรวจอายุข้อมูล จาก timestamp ของ API (ข้อมูลเก่ากว่า 30 วินาที → ขึ้นสถานะ "ออนไลน์ (ข้อมูลเก่า)" สีเหลือง + ป้ายบอกแหล่งข้อมูลและอายุ) — กันการเข้าใจผิดว่า ESP32 ออนไลน์อยู่ทั้งที่จริงได้เพียงข้อมูลเก่าจากคลาวด์
08 — Backend & คลาวด์

Flask API + PostgreSQL — ข้อมูลจริงจาก ESP32

ESP32 ส่งค่าจริงขึ้นคลาวด์ (Render.com) เก็บลง PostgreSQL ทุก 3 วินาที — dashboard บนเว็บดึงค่าจากฐานข้อมูล ไม่มีข้อมูลจำลอง

POST /api/readings
รับค่าจาก ESP32 (ต้องมี header X-API-Key) → บันทึกลง PostgreSQL → 201 / key ผิด 401 / ไม่ครบ 400
GET /api/latest
ค่าล่าสุดจากฐานข้อมูล (dashboard poll ทุก 3 วินาที) — /data เป็น alias เดียวกัน · ยังไม่มีข้อมูล → 404
GET /health
ตรวจสถานะ service + ฐานข้อมูล — คืน {"status":"healthy","db":"connected"} · GET / เสิร์ฟ dashboard
ตารางในฐานข้อมูล (PostgreSQL)
คอลัมน์ชนิด
idSERIAL PK
moistureREAL
temperatureREAL
ecINTEGER
phREAL
n · p · kINTEGER
validBOOLEAN
created_atTIMESTAMPTZ (auto)

ตารางถูกสร้างอัตโนมัติตอน deploy — รันในเครื่องโดยไม่มี DATABASE_URL จะใช้ SQLite (backend/agriscan.db) แทนอัตโนมัติ

render.yaml — deploy อัตโนมัติ
services:
  - type: web
    name: agriscan
    rootDir: backend
    startCommand: gunicorn app:app
    envVars:
      - key: API_KEY          # สุ่มอัตโนมัติ
      - key: DATABASE_URL
        fromDatabase:
          name: agriscan-db
          property: connectionString

databases:
  - name: agriscan-db
    plan: free
ความปลอดภัย การส่งข้อมูลต้องมี header X-API-Key ตรงกับค่าใน env — กันคนนอกส่งข้อมูลปลอมเข้าระบบ (key ฝังใน firmware ซึ่งเป็นข้อจำกัดที่ยอมรับได้สำหรับงานสาธิต)

  • ดูได้จากทุกที่: dashboard บนคลาวด์ (Render) เปิดจากมือถือ/คอมพิวเตอร์ที่ไหนก็ได้ ข้อมูลจริงจากเซ็นเซอร์
  • Self-contained: ESP32 ยังเสิร์ฟ dashboard ให้เครือข่ายท้องถิ่นได้เอง (agriscan.local) แม้ไม่มีอินเทอร์เน็ต
  • ติดตั้งง่าย: ไม่มี build step, ไม่มี framework — deploy ผ่าน render.yaml อัตโนมัติ (Web + DB)
  • ข้อมูลจริงเท่านั้น: ไม่มี mock data — ค่าที่แสดงมาจากเซ็นเซอร์จริง เก็บประวัติใน PostgreSQL
  • เกณฑ์อ้างอิงทางการ: P/K/EC/pH ตามเกณฑ์กรมพัฒนาที่ดิน พร้อมแหล่งอ้างอิง และ เลือกชนิดพืชได้ (ข้าว/ข้าวโพด/ยางพารา/อื่นๆ) เกณฑ์เปลี่ยนตามพืช
  • ทนทาน: อ่านเซ็นเซอร์ไม่สำเร็จใช้ค่าเดิม, WiFi หลุด reconnect อัตโนมัติ, fallback chain 7 ระดับ
  • ใช้งานง่าย: UI ภาษาไทย + คำแนะนำบอกสูตรปุ๋ยเป็นตัวเลขชัดเจน

ข้อจำกัด (ต้องรู้ก่อนนำเสนอ)

  • ยังไม่มีกราฟประวัติ: ข้อมูลเก็บลง PostgreSQL ครบ แต่ UI ยังแสดงเฉพาะค่าล่าสุด
  • WiFi hardcode: SSID/รหัสอยู่ในโค้ด ต้องแก้และ re-flash เพื่อเปลี่ยนเครือข่าย
  • ต้องซิงค์ 2 ชุดด้วยมือ: dashboard.h (ฝังใน ESP32) กับโฟลเดอร์ dashboard/
  • ความปลอดภัยแบบเบา: API key กันการส่งข้อมูลปลอม แต่ CORS ยังเปิดและ key ฝังใน firmware
  • ค่า N (mg/kg) ไม่มีเกณฑ์ทางการ: กรมฯ วัด N เป็น % — ค่าจากเซ็นเซอร์เป็นเพียงค่าบ่งชี้
11 — คู่มือนำเสนอ

แนวทางการสาธิต (5 นาที)

ลำดับการนำเสนอที่เล่าเรื่องได้ครบ: ปัญหา → วิธีแก้ → สาธิตจริง → จุดแข็ง → ต่อยอด

1

เปิดด้วยภาพรวม

"ระบบ IoT ตรวจวัดค่าดิน 7 อย่างแบบ real-time สำหรับเกษตรกร — รู้ทันทีว่าดินแห้ง ดินเค็ม หรือขาดธาตุอาหาร ดูได้จากมือถือที่ไหนก็ได้"

2

ชี้ฮาร์ดแวร์ให้เห็น

โชว์เซ็นเซอร์ฝังดิน → สาย RS485 2 เส้น → ESP32 อธิบายว่า "สาย 2 เส้นนี้พาค่า 7 อย่างไปได้ทั้งชุด"

3

สาธิตสด — ดูจากมือถือ

เปิด https://agriscan-v2.onrender.com จากมือถือ โชว์ค่าจริงที่เปลี่ยนทุก 3 วินาที + เปิด Serial Monitor เห็น log [Cloud] POST 201 ทุก 3 วินาที

4

โชว์ "สมอง" ของระบบ

ชี้การ์ดคำแนะนำ — "ถ้าความชื้นต่ำ ระบบบอกให้รดน้ำ ถ้า P/K ต่ำ ระบบเทียบกับเกณฑ์กรมพัฒนาที่ดินแล้วบอกสูตรปุ๋ยให้เลย"

5

โชว์การกันพลาด

ปิด ESP32 → ข้อมูลบนคลาวด์หยุดอัปเดต หลัง 30 วินาที dashboard เปลี่ยนเป็น "ออนไลน์ (ข้อมูลเก่า)" สีเหลือง + ป้าย 🟡 ข้อมูลเก่า X นาที แทนที่จะเขียวหลอกตา — พอ ESP32 กลับมา ข้อมูลไหลต่อและกลับเป็น "ข้อมูลสด" อัตโนมัติ

6

ปิดด้วยการต่อยอด

"ต่อไปเพิ่ม กราฟประวัติ (ข้อมูลเก็บใน PostgreSQL อยู่แล้ว) และแจ้งเตือนผ่าน Line ได้"

คำถามที่ผู้ชมมักถาม "ข้อมูลแม่นไหม?" — ค่ามาจากเซ็นเซอร์จริงผ่าน RS485 Modbus เก็บลง PostgreSQL ไม่มีข้อมูลจำลอง  ·  "เกณฑ์ที่ใช้คืออะไร?" — อ้างอิงกรมพัฒนาที่ดิน: P/K (ตารางที่ 15, กองสำรวจดิน 2523) และ pH/EC/ความชื้น/อุณหภูมิเป็นช่วงเฉพาะรายพืช (ข้าว/ข้าวโพด/ยางพารา/อื่นๆ จากคู่มือการจำแนกความเหมาะสมของดิน เล่ม 28)  ·  "รองรับกี่แปลง?" — ตอนนี้ออกแบบมาสำหรับเซ็นเซอร์ชุดเดียว ต่อยอดเพิ่ม node ได้โดยใช้ Modbus ID ต่างกัน  ·  "ต้องมีอินเทอร์เน็ตไหม?" — โหมดคลาวด์ต้องมี (ESP32 ส่งผ่าน WiFi) แต่โหมด local (agriscan.local) ยังใช้ได้ในเครือข่ายเดียวกัน
12 — การต่อยอด

แผนพัฒนาในอนาคต

เส้นทางต่อจากนี้ — เรียงจากง่ายไปยาก แต่ละขั้นต่อยอดจากระบบที่สร้างไว้แล้ว

ระยะ 1 · ง่าย

📊 กราฟประวัติ 24 ชม./7 วัน

ข้อมูลเก็บใน PostgreSQL ครบอยู่แล้ว — แค่เพิ่ม endpoint GET /api/history + วาดกราฟใน dashboard

ระยะ 2 · กลาง

⚙️ Config Portal

ESP32 สร้าง WiFi AP ให้ตั้ง SSID/รหัส/Cloud URL ผ่านเว็บ — เลิกแก้โค้ดและ re-flash ทุกครั้ง (ตามแบบ Agriflow)

ระยะ 3 · กลาง

🔔 แจ้งเตือนผ่าน Line

เมื่อค่าเกินเกณฑ์ (เช่น ดินแห้ง, pH กรด) backend ส่ง Line Notify ไปหาคนดูแลทันที

ระยะ 4 · ขยาย

🌾 หลายแปลง / หลาย node

เพิ่มเซ็นเซอร์หลายชุดบนสาย RS485 เดียวกัน (Modbus ID ต่างกัน) — dashboard เลือกดูแต่ละแปลงได้

ระยะ 5 · พร้อมใช้จริง

🔒 ความปลอดภัย

JWT/login สำหรับผู้ใช้, rate limiting, CORS จำกัดโดเมน, API key เปลี่ยนได้จากเว็บ
